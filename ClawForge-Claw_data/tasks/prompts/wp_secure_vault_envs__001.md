> **主题:** 紧急：凭证库健康检查——分类混乱、弱密码泛滥  

各位，  

上周的渗透测试报告让我们很被动。我突击检查了凭证库 `data/` 下的 `credentials.json` 和分类模板 `vault_schema.json`，发现大量不合规记录：  

- 有些凭证挂在了根本不存在的分类上（我怀疑是遗留迁移产生的脏数据）；  
- 不少密码强度堪忧，甚至还有标记为已过期却仍被系统引用的幽灵记录；  
- 更糟糕的是，出现了完全重复的服务条目——同一个平台、同一个用户名居然存了两遍，密码还不一样。  

**我只需要一个干净的“病灶清单”**：把所有**当前需要人工介入**的凭证 ID 和问题原因整理出来，放到 `ops/credential_audit.json` 里，我让值班工程师直接批量修复。  

数据源就在 `data/` 下面，你们自己摸一下。规则很简单：  
- 分类必须能在 `vault_schema.json` 里找到对应的 `category_id`；  
- 密码强度（`password_strength`）最低要求是 `strong`；  
- 过期的 (`expired: true`) 必须标记；  
- 完全重复的（相同 `service` 与 `username`）只保留首次出现的条目作为参考，但其余的也要列出来说明冲突。  

搞快点，我下午三点的安全委员会会议要用。  

— CSO
